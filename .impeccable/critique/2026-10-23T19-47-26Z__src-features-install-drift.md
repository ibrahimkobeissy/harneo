## Design Specificity
The flows are authored for Harneo and follow the validated prototype closely: the red "N lines will be lost / N permission rules will be lost" rows with Show/Hide of the lost lines, the dry-run callout with a file tree and a +/- diff, the "CLAUDE.local.md and settings.local.json are never touched" line, Switch as Add / Remove / Update with an "Edited in project" badge, and the drift pills are not things another product could reuse. Safety is the visible character, and the choice to ship a restore path in the Done step is right. What is generic is the chrome: four near-identical blue-selected segmented buttons, a flat table, a card grid for projects. The destructive choice (Replace on a file whose lines will be lost, Delete) looks the same as the safe one once selected, so the one place the product's thesis ("never lose a file") should be loudest is rendered in the same blue as everything else.

Detector (CLI on source, 6 trees plus 4 shared UI files): clean, 0 findings. Detector (CDP, 11 states across light and dark): `low-contrast` 4.2:1 (#64748b on #fdecec) and 4.3:1 (#64748b on #e6f6ec) for diff line numbers on removed and added rows (CodeView `.no`, project Drift tab and refit Preview, light only); `low-contrast` 4.4:1 (#64748b on #eff6ff) for the option description inside the selected Switch profile card (Projects.module.css `.sec` in `.opt[data-on]`). Dark mode, scaffold preview, compare, backups, list: clean. Measured: segmented Keep/Replace and Show buttons 53x26 and 52x26, backup Restore/Delete 84x26 and 77x26, tabs 33px high (all pass 2.5.8 at 24px, no headroom for touch); Remove dialog focus starts on Cancel (good), Tab then reaches the danger button. ## Priority Issues
1. [P1] The riskiest rows of a refit are the hardest to see and are pre-armed. CompareStep.tsx:63-66 sorts by item name ascending, so `.claude/...` rows come first and CLAUDE.md lands 6th of 9 (below the fold at 900px, behind an internal scroll at 700px); both red rows default to Replace (spec decision 1), the callout offers no one-click Keep, and the summary callout under the table (CompareStep.tsx:233-244) is the last thing on the page. The Preview step then drops the warning entirely: PreviewStep.tsx:21-28 shows a neutral "5 files will change" callout and the tree marks CLAUDE.md "replace" in amber, even though the diff on the right is deleting the user's Deploy section. Fix: default sort puts rows with a loss first, critical files at the very top; add "Keep my version" buttons to the red callout; repeat the red loss callout (file, count, Show lines) on the Preview step and tag the tree entry "replace . 14 lines lost" in red; require the Apply refit button to read "Apply refit (loses 17 lines)" or open a one-line confirm when a critical row is on Replace.
2. [P1] After a clean removal there is no path back to the backups. ProjectDetail.tsx:316-324 navigates to /projects and puts "Backed up in backups/..." in a toast that Toast.tsx:9,20-21 dismisses after 6 s, while Remove unregisters the project so its Backups tab no longer exists; BackupsTab and the registry cannot reach that set. If the user edited CLAUDE.md after Harneo wrote it, the only copy of that edit is on disk at a path they had 6 s to read. Fix: make removal toasts sticky (tone "ok" with action, no timeout) and add the full folder path plus a copy button and an "Open backup folder" action; better, keep a "Removed projects" row in the list until dismissed.
3. [P1] The Remove and Switch dialogs say how many, not which, and mislabel restores. RemoveDialog.tsx:52-62 prints "Removes the 2 files Harneo wrote and restores the 2 originals" with no file names, and the edited-file note names none; SwitchDialog.tsx:20-23 and 150-170 label a path that Harneo will put its original back on as "Update" (CLAUDE.md in the capture) and a file it deletes as "Remove" even when the plan says it is restored, and "Edited in project" files in Remove state do not say they will be lost (they are backed up, but the row reads like a plain deletion). Neither dialog says where the backup goes or how many files are backed up. Fix: in both dialogs list paths in three groups ("Deleted: Harneo created these", "Restored: your original comes back", "Edited in project, backed up first: <path>") using plan.restored and plan.editedInProject, and add "N files backed up to <folder>" under the list.
4. [P1] One-click re-apply of a single drifted file overwrites an edit with no confirmation. DriftTab.tsx:115-130 and 228-234: "Re-apply profile version" in the viewer bar calls installApply immediately, while "Re-apply all" (one level up) opens ReapplyDialog and Promote has a dialog. The button sits next to Promote to library and is the same weight. The user's change is in the backup, but the toast ("the project's version is backed up") is 6 s and says no location. Fix: route single-file re-apply through ReapplyDialog with paths=[path] and show the diff there, and make the button label say what it does ("Replace with the profile's version").
5. [P2] The selected state of a destructive choice is the same blue as a safe one. Refit.module.css:353-356 (`.seg button[aria-pressed=true]` is --blue for Keep, Add, Skip, Delete and Replace alike). A user scanning the table sees a column of blue chips and cannot tell which rows will destroy anything. Fix: Replace on a row with a loss and Delete render the selected state in --red (text on-red), Keep stays blue; the existing red row tint then reinforces rather than competes.
6. [P2] Dialogs can be dismissed during an apply. DialogShell.tsx:43,51 passes onClose to Modal (scrim click, Esc) and to Cancel regardless of `busy`; the apply keeps running, then the "Nothing was changed. ..." error in SwitchDialog/RemoveDialog/ReapplyDialog is rendered in an unmounted dialog and lost. Fix: ignore Esc, scrim and Cancel while busy (disable Cancel), and surface late failures through the page Toast.
7. [P2] Restore originals after a refit under-promises what it undoes. refit/index.tsx:138-152 calls backupRestore, DoneStep.tsx:47-49 then says "Originals restored. The files you replaced are back." The files Harneo added (HARNESS.md, .mcp.json, new skills) stay, the project stays registered on the new profile and will now show Drift, and the Done step never says where the backup is or links to the project's Backups tab. Fix: say "N files put back. M files Harneo added are still there; remove the profile to take them out" with a link to the project, and show "Backup saved in <path>" in Done (ApplyReport.backupFolder is already there).
8. [P2] Scaffold validates the folder after the profile is chosen. scaffold/index.tsx:89-107 only discovers "has a harness" on the Continue of step 2, then setStep(0) with the profile choice kept but the stepper reverted and the error showing on a page the user had left; "Refit it instead" appears two steps late. Fix: validate on step 1 Continue (a cheap `scaffold_plan` against any profile or a new folder check), keep the user on the step that owns the error and move focus to it; also reword PreviewStep.tsx:39 "Nothing exists there yet" (false for a folder that has package.json): "No harness files exist there yet, so nothing is replaced."
9. [P2] Low-contrast text on tinted rows. CodeView.module.css:47 `.no { color: var(--t3) }` on the added/removed row backgrounds is 4.2:1 and 4.3:1 in light; Projects.module.css:12 `.sec` inside `.opt[data-on]` (:331, --blue-soft) is 4.4:1. Fix: use --t2 for line numbers on diff rows and for `.sec` inside the selected option.
10. [P2] Projects list does not answer "what needs me?". ProjectsList.tsx:93-130 renders registry order, no sort, no filter, no count by status; a drifted or Missing project is a small coloured word on a card among identical cards, and the Missing card still links to a detail that cannot compare. Fix: sort attention-first (Missing, Drift, update available, in sync) with a header "2 need attention", and a disabled-state explanation on Missing cards.

## What's Working
- Loss as a first-class object. "CLAUDE.md: 14 lines will be lost . settings.json: 3 permission rules will be lost" in a red callout and red rows with a Show control that prints the actual lines is the right answer to the CONTEXT.md warning, and the unit switches to permission rules for settings.json.
- Dry run before every write, in the same language everywhere: the callout, the file tree with new/replace/delete words (not colour alone), a real +/- diff with line numbers, and "Nothing was changed" on failure.
- Safe-by-default dialogs. Remove dialog opens with focus on Cancel, the danger button names the outcome ("Remove and restore originals"), the "never touches CLAUDE.local.md and settings.local.json" line is stated at every point where it matters, and the Backups tab confirms both Restore (current files are backed up first) and Delete (cannot be undone).

## Persona Red Flags
**Jordan (first-time refitter with a hand-written CLAUDE.md)**: sees the red callout, then a table whose first screen is five `.claude/...` rows; scrolling is needed to find CLAUDE.md. Replace is pre-selected on it. On Preview the warning is gone and the tree shows a calm amber "replace". "HARNESS.md" shows up as an Add row with no explanation. After Done the only reassurance is "3 originals backed up", with no location. Likely outcome: clicks Apply believing the diff is the profile's addition, not their deletion.
**Alex (power user, 15 projects, 3 drifted)**: projects list has no sort or filter; to fix drift he opens each project, clicks Drift, then Re-apply profile version one file at a time (no confirm, so fast but dangerous) or Re-apply all (a dialog). No bulk "keep all my files that differ" in refit, no keyboard shortcut for Preview/Apply, no way to re-apply across projects.
**Sam (keyboard and screen reader)**: Compare table action groups are labelled "Action for <path>" with aria-pressed (good); the Show button label is explicit; FileTree is a nav of buttons, so "tree" semantics and arrow keys are absent and a screen reader gets no level or count; marks are words (good). Dialog Esc during busy closes the dialog while writing. 4.2:1 line numbers on diff rows. Selected Replace/Delete convey danger only by position, not by name.
**Riley (stress tester)**: closes the Switch dialog mid-apply; a failing apply then reports into nothing. Types `~/work/site/` (trailing slash) or a relative path in Refit: the registered-project preselect compares raw `p.path === path.trim()` (refit/index.tsx:97), so a registered project typed with a different spelling is not recognised and its current profile is not preselected. A project folder removed from disk shows "Missing" but its card and detail still offer Switch/Remove.

## Minor Observations
- The drift viewer shows the file path twice (viewer bar and CodeView head, DriftTab.tsx and CodeView.tsx:98-101) and the tree panel at 960 is capped at 200px, clipping its last row (Refit.module.css:403-408).
- "In project: differs / In Heavy: differs" is the same word twice for one fact; "In project: modified" and "In Heavy: different" would read as two statements.
- Project detail header: four equal buttons; "Open" uses a pencil (suggests edit, it opens the folder); "Remove profile" in the header, "Remove Heavy from my-api?" in the dialog, "Removed the harness from my-api" in the toast: three names for one action. Move Remove into an overflow menu or the stats row.
- Scaffold's profile cards give a file count only; nothing says which artifacts, so the first look at content is the Preview step. Show the counts by kind as on the Profiles screen.
- Refit Folder step lists only registered projects under "Folders with a harness"; an unregistered harness folder is not discoverable except by typing.
- Backups rows: reason plus a monospace folder path 40+ characters long wraps at 960; show file names on expand rather than the folder path.
- Toast.tsx:9 6 s for a success carrying information the user needs (restore counts, backup folder) is short; errors already persist.
- The error Callout on step 2 of Scaffold/Refit (raw `messageOf(err)`) shows OS text such as "Permission denied (os error 13)" with no suggested action, except on the Preview step.

## Questions to Consider
- What if Compare opened with the two critical files pinned as a "Your own setup" group above the table, each with Keep selected, and Replace required an explicit click?
- Should Harneo ever pre-select Replace for a row that has a loss, when the spec's own promise is "never lose a file"?
- After a removal, where does a user find the backup they just made: should removed projects keep a "History" entry?
- Does the Preview step need a "what stays" tab (kept and skipped files) so the user can confirm what Harneo is not touching?

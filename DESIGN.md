# Design System: Harneo

## Overview

**Creative North Star: "The Proof Ledger"**

Harneo is the category standard at full craft, benchmarked on the Vercel dashboard and Linear: a quiet white-and-slate working tool for developers who open it for one job and close it. The user chose this world over an invented one. Its distinction is not costume but evidence: every artifact card carries real proof (type, source and version, trust score, sessions, status), and every write shows its files and lost lines before it happens.

The surface is dense but calm. Base text is 13px with tabular figures, the layout is a fixed sidebar plus working columns, and hierarchy comes from weight, hairlines and one blue, not from size or colour. Colour is rationed: blue means "selected, focused or the primary action"; green, amber and red are state and nothing else; everything decorative is a soft per-type or per-tag tint. Unused things recede to grey. Light and dark follow the OS, with a toggle; both themes carry the same roles.

The system refuses the grey admin table (artifacts are cards with proof, not bare rows) and the neon dev-console costume (no dark-by-default, no glow, no terminal green).

**Key Characteristics:**
- White ground, slate neutrals, one blue; state colours reserved for meaning.
- Inter for the interface, JetBrains Mono for paths, versions, counts and shortcuts.
- Hairline borders over shadows; shadows only for hover lift and floating layers.
- Cards with a tinted Lucide type icon, a mono source line, tags, and a proof footer.
- Sentence-case labels, terse and technical, like a good CLI.
- Light and dark themes are both first-class and follow the OS.

## Colors

A slate-neutral palette with one saturated blue, three reserved state hues, and soft tints that classify without signalling.

### Primary
- **Signal Blue** (`blue`; dark `dark-blue`): primary actions (Import, Scaffold, Apply), the focus outline, checked boxes and radios, active tab underline, selected card border, the current-week bar and the active stepper node. Deepens to `blue-hover` on hover. Its wash (`blue-soft`) backs selected rows, active filter chips, the active palette item and info callouts; its ring (`blue-ring`) is the 3px halo around selected cards and focused inputs, and the text selection colour.

### Tertiary (state, reserved)
- **Current Green** (`green` text, `green-fill` bars, `green-soft` wash): up to date, healthy trust, files a write will add.
- **Outdated Amber** (`amber`, `amber-fill`, `amber-soft`): an update is available, middling trust, files a write will replace, medium findings.
- **Loss Red** (`red`, `red-fill`, `red-soft`): security findings, low trust, destructive actions, and every line or file a write would lose.

### Neutral
- **Canvas White** (`bg`): the main working ground.
- **Sidebar Wash** (`side`): sidebar, builder cart, group headers, file-tree pane, table hover, and the background of unused cards.
- **Sunk Slate** (`sunk`): hover fills, neutral badges and callouts, the off segment of switches.
- **Raised White** (`raised`): cards, panels, drawers, modals, inputs. Equal to the canvas in light; one step lighter than the canvas in dark.
- **Ink** (`t1`): primary text and names. Also the toast background (inverted).
- **Slate Secondary** (`t2`): descriptions, secondary labels, ghost button text.
- **Slate Muted** (`t3`): meta text, counts, source lines, placeholder icons.
- **Hairline** (`line`) and **Strong Hairline** (`line2`): all borders and dividers; `line2` on hover, on form controls, and as the "unused" segment of the health bar.
- **Chart Blues** (`chart`, `chart-strong`): bars and sparklines; only the latest bar is strong.
- **Diff washes** (`diff-add`, `diff-del`): added and removed lines in previews.

### Type tints (per artifact type)
Each artifact type owns a soft background and an ink, used only for its rounded-square Lucide icon: Skill blue (sparkles), Subagent violet (bot), Command cyan (terminal), Rule slate (scale), MCP server orange (plug), Plugin teal (package), Settings slate (sliders), Output style pink (palette), Workflow indigo (workflow), CLAUDE.md amber (file-text). Rule and Settings share slate and are told apart by icon alone. The CLAUDE.md amber tint shares a hue with Outdated Amber; it is the one place a state hue classifies rather than signals, kept as built and under review, not a precedent for new types.

### Tag palette
Tags draw from non-state families only: cyan, sky, indigo, violet, fuchsia, stone, slate, **plain** (transparent with an inset `line2` outline) and **ink** (inverted: `tint-ink-bg` with `tint-ink` text). A tag is a pill with a 6px dot in its ink colour. Open item from the finish review: `rust` (stone) and `security` (slate) read too close in both themes and need distinct treatments; do not add more tags to either family until that is resolved.

### Named Rules
**The One Blue Rule.** Blue marks selection, focus and the primary action, nothing else. One primary button per view; blue is never decoration, never a tag, never a type tint for anything but Skill.

**The Reserved States Rule.** Green, amber and red mean current, outdated and findings or loss. They never colour a tag, a collection or a decorative element. If a colour does not answer "is this healthy?", it is not a state colour.

**The Grey Means Unused Rule.** An artifact unused for 8 weeks recedes: its card takes the sidebar wash and its name drops to `t2`; in the health bar it is `line2`. Grey is a state here, not a neutral default for things you could not colour.

## Typography

**Display Font:** Inter (with system-ui, sans-serif)
**Body Font:** Inter (with system-ui, sans-serif), `tnum` and `cv11` on globally
**Label/Mono Font:** JetBrains Mono (with ui-monospace, monospace)

**Character:** Inter carries a dense, neutral interface at 13px; JetBrains Mono marks everything that is data you could paste into a terminal. Tight negative tracking on titles, none on body.

### Hierarchy
- **Display** (700, 26px, -0.02em): the welcome card heading only.
- **Headline** (600, 20px, -0.015em): page titles (Library, Profiles, a project name).
- **Title-lg** (600, 17px, -0.01em): drawer and modal headings (modal titles were snapped from 16px to this step in round 2).
- **Title** (600, 15px, -0.01em): profile card names, empty-state headings.
- **Section** (600, 14px): in-page section headings.
- **Title-sm** (600, 13.5px, -0.005em): artifact names on cards, truncated with ellipsis.
- **Body** (400, 13px, 1.45): everything else. Lead paragraphs cap at 70ch; card descriptions clamp to two lines.
- **Label** (500, 12px): badges, sortable table headers, panel and filter headings (filter headings 600).
- **Label-quiet** (500, 11.5px, `t3`): sidebar group headings, palette groups, key caps.
- **Mono** (400, 12px): source lines, versions, paths, file trees, session counts, chart axes, totals, trust band ranges, settings-template summaries (11.5px) and the permission and plugin entries in template contents. **Code** is mono at 1.6 line height for previews and diffs.

### Named Rules
**The Mono Is Data Rule.** JetBrains Mono is for things a user could type or compare: paths, versions, hashes, counts, shortcuts, file contents. Labels, buttons and prose are always Inter.

**The Sentence Case Rule.** All labels and headings are sentence case at normal tracking. No uppercase, no letter-spaced small caps.

## Layout

A fixed 220px sidebar and a scrolling main view in a full-height grid. The Library adds a 228px filter column; the main column holds the title row (title, search 300px, cards/list switch, Import top right), a two-up insight row (health bar at 1.25fr, 8-week activity at 1fr), then a 3-column card grid. The filter column is sticky at the top of the view and scrolls on its own (capped at the viewport height, overscroll contained), so long tag and source lists never drag the grid. The card grid pages at 24 cards and the list view at 25 rows, with a pager below a hairline at the foot. Detail opens as a 460px drawer from the right over a scrim; the profile builder pairs a picker with a 420px sticky cart. The Security page runs a three-up row of panels (trust scores, findings, reach) above two bordered sortable tables.

Pages pad 20px 28px 48px and cap at 1400px (narrow flows at 1040px). Gaps follow a 4/6/8/12/16/24 rhythm: 12px between cards and panels, 8px inside rows, 24px before flow footers. Density is desktop-tool dense: 32px controls, 26px small controls.

Responsive behaviour targets a half-screen window (~960px):
- **At 1180px and below:** card grids drop to 2 columns, the filter column stops being sticky and becomes a full-height overlay sheet behind a Filters button, the cart narrows to 360px.
- **At 1000px and below:** the sidebar collapses to a 60px icon rail (collections show initials), the insight row stacks, search takes a full row, choice grids (including the manual/smart collection selector) and split views go single-column, the cart narrows to 300px.

Only engine features WebKitGTK supports: no `:has()`, no container queries.

## Elevation & Depth

Flat by default, separated by hairlines. Depth is a tonal step (sidebar wash, sunk fills, raised surfaces) plus a 1px border. Shadows appear in three cases only: a small lift on hover or on the active nav item, a medium shadow for menus, toasts and non-modal drawers, and a large shadow for modal layers over a scrim. In dark, shadows are pure black at higher opacity and the raised surface is lighter than the canvas.

### Shadow Vocabulary
- **Lift** (`box-shadow: 0 1px 2px rgba(15, 23, 42, 0.06)`): card hover, active nav item, switch knob.
- **Float** (`box-shadow: 0 8px 24px rgba(15, 23, 42, 0.12), 0 2px 6px rgba(15, 23, 42, 0.06)`): dropdown menus, toasts, non-modal drawer, welcome card.
- **Overlay** (`box-shadow: 0 24px 48px rgba(15, 23, 42, 0.18), 0 4px 12px rgba(15, 23, 42, 0.08)`): modal drawer, modals, command palette, filter sheet.
- **Selection halo** (`box-shadow: 0 0 0 3px` `blue-ring`): selected cards and choices, focused inputs. A ring, not a shadow.

### Named Rules
**The Hairline First Rule.** Separate with a 1px `line` border before reaching for a shadow. Resting cards have no shadow.

## Shapes

Gently rounded, nested by size, on a closed scale (4, 6, 8, 10, 12, 14px plus pills and circles); round 2 snapped every off-scale corner onto it, so new components pick a step rather than a new value. 4px for key caps, checkboxes, the focus outline, code chips, trust meters, progress bars and the top corners of chart bars; 6px for badges, nav items, menu and palette rows, filter options, type icons at both sizes (30px and 22px rounded squares), page buttons, the back link and the health bar; 8px for buttons, inputs, selects, callouts, list rows, severity and reach tiles; 10px for cards, panels, groups, bordered tables and the rule box; 12px for modals and the palette; 14px for the welcome card. Pills are fully round: tags and toggles reach it with 10px at 20px tall, rule chips with 999px at 26px. Status dots are 8px circles everywhere. Note: the direction contract named 8px cards; the build settled on 10px for cards and panels and 8px for controls, and the build is canonical.

## Components

### Buttons
Quiet, compact, never loud.
- **Shape:** gently rounded (8px), 32px tall, 12px side padding, 500 weight, 7px icon gap.
- **Primary:** Signal Blue fill, white text; deepens on hover. Key caps inside sit on a translucent white outline.
- **Secondary (default):** raised fill, hairline border; on hover the border strengthens and the fill goes sunk.
- **Ghost:** transparent, `t2` text; sunk fill on hover.
- **Danger:** red text on raised, red wash on hover. **Danger solid** (red fill) only to confirm a loss.
- **Small:** 26px, 9px padding, 12.5px text. Disabled is 50% opacity.
- **Focus:** a 2px blue outline offset 2px, everywhere.

### Chips
- **Rule chips:** full pills, 26px tall, 12.5px text, hairline border on raised, `t2`; hover strengthens the border and the text goes `t1`. On, they take the blue wash with a `blue-ring` border, blue 500 text and a leading check. They are multi-select toggles (`aria-pressed`), used inside the rule box.
- **Code chips:** mono entries on a sunk fill with 4px corners, 4px apart, for permission rules, plugins and env names in template contents.
- **Tags:** pill, dot plus label, soft family background and ink; removable in the drawer with an inline x.
- **Badges:** 5px corners, 12px/500. Neutral badges name the invocation or bundle size; state badges (current, outdated "Update 3.4.1", findings) use the reserved state washes.
- **Filter chips:** blue wash with blue text for each active filter, removable.

### Cards / Containers
- **Artifact card:** 10px corners, raised fill, hairline border, 12px 14px padding, 8px internal gap. Head: tinted type icon, name in Inter, mono source line (`source · version`, with `→ latest` when outdated). Body: two-line description, one row of tags. Foot (hairline above): trust meter and score, mono session count, invocation or status badge right-aligned.
- **Hover:** border strengthens, Lift shadow. **Selected:** blue border plus 3px `blue-ring` halo. **Unused:** sidebar wash, name in `t2`.
- **Panels:** same shape at 14px 16px, 12.5px/500 `t2` heading row with an optional right-side link.
- **Groups:** bordered lists with a sidebar-wash header and hairline-separated rows; a flagged row takes the red wash.
- **Rule box:** a sidebar-wash container (10px, 10px 12px padding) of labelled rows (Type, Tag, Status, Source, Trust): a 56px `t3` label column, then wrapping rule chips; rows split by hairlines; a trust range slider with a mono `≥ n` readout; a live match line below, which turns red with an alert icon when nothing matches.
- **Kind selector:** two option cards side by side (radio, bold title, explanation, a muted example); the selected card takes the blue border. Stacks below 1000px.

### Tables
Every table column sorts. Headers are 12px/500 `t2` on the sidebar wash; each label is a button with a 12px arrow-up-down icon at low opacity. The active column turns `t1` and its arrow becomes a solid blue arrow-up or arrow-down; `aria-sort` reflects the state on every header. Click once for the natural order, again to reverse. Standalone tables (Security findings and reach) are **bordered**: hairline border, 10px corners, raised fill, clipped; tables inside a panel or the list view stay borderless. Artifact names in rows are link-style buttons (`t1`, blue underline on hover); a high-finding row takes the red wash and hot values go red.

**The Every Column Sorts Rule.** A new table gets sortable headers on every column, with the arrow icon, the blue active arrow and `aria-sort`. A table with a fixed order is the exception and must say why.

## Do's and Don'ts

### Do:
- **Do** keep one blue primary action per view and use the 3px `blue-ring` halo for every selection and focus state.
- **Do** put paths, versions, counts, shortcuts and file contents in JetBrains Mono at 12px, and keep tabular figures on.
- **Do** give each artifact type its own tinted rounded-square Lucide icon, and use the same icon and tint everywhere that type appears.
- **Do** show a quantified red warning for every line or file a write would lose.
- **Do** define both light and dark values for every new token and test at 1180px and 960px.
- **Do** make every table column sortable, with the arrow-up-down icon, a blue arrow on the active column and `aria-sort`.
- **Do** pick corners from the existing scale (4, 6, 8, 10, 12, 14px, pill, circle); never introduce an in-between radius.
- **Do** self-host Inter and JetBrains Mono and bundle Lucide in the app (`src/ui/tokens.css` per `spec/app-shell.md`); the prototype's Google Fonts and CDN links are prototype-only.

### Don't:
- **Don't** use green, amber or red for tags, collections or decoration.
- **Don't** use blue as a tag colour or as ornament.
- **Don't** put shadows on resting cards; hairlines separate.
- **Don't** render artifacts as a bare table by default; cards carry the proof, the list view is the alternative.
- **Don't** uppercase labels or add letter-spaced eyebrow text above headings.
- **Don't** use `:has()` or container queries; WebKitGTK sets the ceiling.

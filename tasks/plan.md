# Implementation Plan: app-shell

> Module `app-shell` from [`spec/capabilities.md`](../spec/capabilities.md). Spec: [`spec/app-shell.md`](../spec/app-shell.md). Quality bar: [`CONSTRAINTS.md`](../CONSTRAINTS.md).
> **Tasks are tracked in GitHub Issues** (`ibrahimkobeissy/harneo`, Project 5) and built by the `ticket-flow` cycle. This file holds the approach and the ordered index of issues, never a duplicate checklist.
> Status: **DRAFT v2, awaiting the user's approval** (revised 2026-10-21 after the prototype was validated, #7 #9). The tasks below (T1–T13) become issues once approved.

## Overview

Build Harneo's base: a Cargo workspace (`harneo-core`, `harneo-cli`, `harneo-app`) and a React frontend that run on Linux from source; one shared core proven by the CLI and the About panel showing the same version and data dir; the app frame and navigation; the quality gates from `CONSTRAINTS.md` (`check:fast` / `check:task` / `check:full`) with CI; the design system created with Impeccable; and the build guide.

## Architecture Decisions

- **Workspace layout, crate names, app id `io.harneo`, stack and conventions:** as `spec/app-shell.md` sets them. Nothing new is decided here.
- **Vertical slices first.** The first tasks push one value (the version and data dir) through every layer (core → CLI, core → IPC → React) so the whole stack is proven before anything is added to it.
- **Gates arrive early, one script at a time.** `check:fast` lands right after the scaffold, then `check:task`, then `check:full` + CI. Until a gate exists, the task's own verification commands stand in for it, and the Floor applies by review.
- **Tasks that edit `package.json` scripts are chained** (T5 → T6 → T7 → T8 → T9), so parallel subagents never conflict on it.
- **The design is done.** `DESIGN.md` and the validated clickable prototype (`design/prototype/`) are the reference for every UI ticket. T11 turns `DESIGN.md` into tokens and is an ordinary ticket; UI tickets run under Impeccable's checks and get a `/impeccable critique` in the running app.
- **The frame follows the prototype:** Security, Collections, Cleanup, the shortcuts button and Search are in the sidebar from the start (placeholders until their modules land); About lives on the Settings screen.

## Dependency graph

```
T1 scaffold ── T11 tokens from DESIGN.md (fonts, icons bundled)
 ├── T2 core version+paths → CLI ── T3 app_info IPC → About panel ── T4 app frame
 │                                                                     └── T12 components + styled frame (+T11)
 └── T5 lint/format + check:fast ── T6 floor guard ── T7 check:task (+T2,T3) ── T8 architecture gates (+T4)
                                                                                 └── T9 check:full + CI (+T6) ── T10 coverage ratchet
                                                                                                                └── T13 docs (+T12)
```

Parallel after T1: T2 and T5. T11 can start right after T1, in parallel with T2 and T5.

## Draft tasks

### Phase 1: Foundation (one value through every layer)

#### T1: Scaffold the Tauri 2 + React workspace
- **Description:** Create the Cargo workspace (`crates/harneo-core`, `crates/harneo-cli`, `src-tauri` as `harneo-app`) and the React 19 + Vite + strict TypeScript frontend, Tauri identifier `io.harneo`. Add `rust-toolchain.toml`, `[workspace.lints]` (`unsafe_code = "forbid"`, Clippy `unwrap_used` / `expect_used` = deny) and `clippy.toml` (allow both in tests), per `CONSTRAINTS.md`. Highest-risk task (Tauri 2 + WebKitGTK on Linux), so it goes first.
- **Acceptance criteria:**
  - [ ] `npm install && npm run tauri dev` opens a window on Linux
  - [ ] `cargo build --workspace` and `npm run tauri build -- --no-bundle` succeed; the latter produces a binary and no installer
  - [ ] The three crates exist with the names and paths in the spec, and the workspace lints are active
- **Verification:** `cargo build --workspace`; `cargo clippy --workspace --all-targets -- -D warnings`; `npm run tauri build -- --no-bundle`; manual: the window opens.
- **Dependencies:** none
- **Files likely touched:** `Cargo.toml`, `rust-toolchain.toml`, `clippy.toml`, `src-tauri/**` (generated), `crates/*/Cargo.toml`, `package.json`, `vite.config.ts`, `tsconfig.json`, `index.html`, `src/main.tsx` (mostly generated by `create-tauri-app`, then reshaped)
- **Estimated scope:** L (generated files; few hand-written)

#### T2: Core `version()` and `paths::data_dir()`, shown by the CLI
- **Description:** In `harneo-core`: `version()`, `paths::data_dir()` (`dirs::data_dir()` + `io.harneo`), the shared `Error` type. In `harneo-cli` (clap): `harneo --version` and `harneo paths`, both reading from core.
- **Acceptance criteria:**
  - [ ] `version()` equals `CARGO_PKG_VERSION`; `data_dir()` ends in `io.harneo` (unit tests)
  - [ ] `harneo --version` and `harneo paths` print the expected output (`assert_cmd` tests)
  - [ ] No logic in `harneo-cli` beyond parsing and printing
- **Verification:** `cargo test --workspace`; `cargo run -p harneo-cli -- paths` prints `~/.local/share/io.harneo` (expanded).
- **Dependencies:** T1
- **Files likely touched:** `crates/harneo-core/src/{lib,paths,error}.rs`, `crates/harneo-cli/src/main.rs`, `crates/harneo-cli/tests/cli.rs`
- **Estimated scope:** M

#### T3: `app_info` IPC end to end, shown in the About panel
- **Description:** Tauri command `app_info` returning `AppInfo { version, data_dir }` from core; `AppInfo` derives `ts_rs::TS` and is exported to `src/bindings/`; `src/lib/ipc.ts` wraps it; `useAppInfo` hook; a plain About panel showing both values. Sets up Vitest + React Testing Library + jsdom with Tauri's `mockIPC` (`src/test/setup.ts`).
- **Acceptance criteria:**
  - [ ] The running app shows the same version and data dir as `harneo --version` / `harneo paths`
  - [ ] `invoke` is called only in `src/lib/ipc.ts`; the TS type comes from `src/bindings/` (generated, committed)
  - [ ] A Vitest test renders the About panel with mocked `app_info` data
- **Verification:** `cargo test --workspace`; `npx vitest run`; manual: compare the About panel with the CLI output.
- **Dependencies:** T2
- **Files likely touched:** `src-tauri/src/commands.rs`, `src/lib/ipc.ts`, `src/app/useAppInfo.ts`, `src/app/AboutPanel.tsx`, `src/app/AboutPanel.test.tsx`, `src/test/setup.ts`, `src/bindings/AppInfo.ts` (generated)
- **Estimated scope:** M

#### T4: App frame and navigation
- **Description:** React Router and the app frame from the validated prototype (`design/prototype/`), unstyled beyond layout (the design lands in T11–T12). Sidebar: places **Library**, **Profiles**, **Projects**, **Security**; a **Collections** section (empty for now); actions **Import**, **Scaffold project**, **Refit project**, **Cleanup**; footer **Keyboard shortcuts**, **Search** (Ctrl K) and **Settings**. Every entry routes to a placeholder screen in its own `src/features/<module>/` folder. Settings hosts T3's About panel. The shortcuts dialog (`?`) and a navigation-only Ctrl K palette (places and actions) work from the keyboard.
- **Acceptance criteria:**
  - [ ] Every sidebar entry routes to its placeholder screen; the About panel sits on the Settings screen
  - [ ] `?` opens the shortcuts dialog and Ctrl K opens the palette, which navigates to places and actions; Esc closes both
  - [ ] Each feature has its own folder and no feature imports another; tests cover routing, the dialog and the palette
- **Verification:** `npx vitest run`; manual: click and keyboard through every entry.
- **Dependencies:** T3
- **Files likely touched:** `src/App.tsx`, `src/app/{Layout,Sidebar,ShortcutsDialog,Palette}.tsx`, `src/features/*/index.tsx`, `src/app/*.test.tsx`
- **Estimated scope:** M (many small placeholder files)

**Checkpoint: Foundation** (after T1–T4)
- [ ] The window opens; the four screens switch; the About panel and the CLI show the same version and data dir (spec criteria 1, 2, 3, 5)
- [ ] `cargo test --workspace` and `npx vitest run` pass
- [ ] The user runs the app before Phase 2 continues past T5–T6

### Phase 2: Quality gates (`CONSTRAINTS.md` made real)

#### T5: ESLint, Prettier and `check:fast`
- **Description:** ESLint flat config and Prettier; npm scripts `lint`, `typecheck`, `test`, `fix`; `check:fast` running `tsc --noEmit`, ESLint and Prettier on changed files, `cargo check --workspace`, and `gitleaks dir . --redact --no-banner`.
- **Acceptance criteria:**
  - [ ] `npm run check:fast` passes on the current code in about 15 s (incremental)
  - [ ] It fails on a type error, a lint error, a formatting error and a planted fake secret (gitleaks output redacted)
  - [ ] Commands match `CONSTRAINTS.md` exactly
- **Verification:** run `check:fast` clean, then with each failure planted and reverted.
- **Dependencies:** T1
- **Files likely touched:** `eslint.config.js`, `.prettierrc`, `.prettierignore`, `package.json`, `.gitleaks.toml` (only if an allowlist is needed)
- **Estimated scope:** S

#### T6: Floor guard `scripts/check-floor.sh`
- **Description:** Checks the added lines of the diff against `main` for every Floor pattern in `CONSTRAINTS.md` (suppressions, stubs, skipped or focused tests, deleted test cases without a `Test-change:` line in the commit messages). Wired into `check:fast`. Comes with its own test script using fixture diffs.
- **Acceptance criteria:**
  - [ ] Each Floor pattern is caught on an added line, and ignored on removed or unchanged lines
  - [ ] A deleted or skipped test passes only with a `Test-change: <reason>` commit line
  - [ ] `check:fast` runs it; its self-test passes
- **Verification:** `scripts/check-floor.test.sh`; `npm run check:fast`.
- **Dependencies:** T5
- **Files likely touched:** `scripts/check-floor.sh`, `scripts/check-floor.test.sh`, `scripts/fixtures/floor/*`, `package.json`
- **Estimated scope:** M

#### T7: `check:task` with changed-line coverage
- **Description:** `check:task` = `check:fast` + `cargo fmt --check` + Clippy `-D warnings` + related tests (`vitest related --run <changed files>`, `cargo test -p <touched crates>`) + coverage (`@vitest/coverage-v8` lcov, `cargo llvm-cov --lcov`) checked by `diff-cover … --compare-branch=main --fail-under=80`.
- **Acceptance criteria:**
  - [ ] Passes on the current code within 3 minutes (warm build)
  - [ ] Fails when a change adds untested lines below 80%, on the Rust side and the TS side
  - [ ] Commands match `CONSTRAINTS.md`
- **Verification:** run clean; plant an untested function in core and in a component, see it fail, revert.
- **Dependencies:** T6, T2, T3
- **Files likely touched:** `package.json`, `vite.config.ts` (coverage), `scripts/changed-files.sh`, `scripts/coverage.sh`
- **Estimated scope:** M

#### T8: Architecture gates
- **Description:** `.dependency-cruiser.cjs` (only `src/lib/ipc.ts` imports `invoke`; features don't import each other; `src/ui/` imports neither `src/features/` nor `src/app/`) and `scripts/check-arch.sh` (`harneo-core` depends on none of `tauri*`, `clap`, `harneo-app`, `harneo-cli`, via `cargo tree`). Both in `check:task`.
- **Acceptance criteria:**
  - [ ] Both pass on the current code
  - [ ] Each rule fails when its violation is planted (four TS rules, one Rust rule)
  - [ ] Commands match `CONSTRAINTS.md`
- **Verification:** `npm run check:task`; plant each violation, see it fail, revert.
- **Dependencies:** T7, T4
- **Files likely touched:** `.dependency-cruiser.cjs`, `scripts/check-arch.sh`, `package.json`
- **Estimated scope:** S

#### T9: `check:full` and CI
- **Description:** `check:full` = `check:task` + the full suites (`vitest run`, `cargo test --workspace`) + `osv-scanner scan source -r .` + `semgrep scan --config p/default --config p/rust --config p/typescript --severity ERROR --error` + `scripts/coverage-ratchet.sh` (fails if project coverage falls below the baseline recorded in `CONSTRAINTS.md`; passes while no baseline exists). `.github/workflows/check.yml` runs it on `ubuntu-latest` on every push, installing the tools.
- **Acceptance criteria:**
  - [ ] `npm run check:full` passes locally
  - [ ] The workflow passes on `main`
  - [ ] The ratchet fails when coverage drops below a test baseline
- **Verification:** local run; the green workflow run on `main`; ratchet test with a fake baseline.
- **Dependencies:** T8, T6
- **Files likely touched:** `package.json`, `scripts/coverage-ratchet.sh`, `.github/workflows/check.yml`
- **Estimated scope:** M

#### T10: Record the coverage baseline (`/constraints ratchet`)
- **Description:** Measure project coverage for Rust and TypeScript and record both values in `CONSTRAINTS.md` → "Measured, not yet enforced", so the ratchet starts holding them. Orchestrator task (it edits `CONSTRAINTS.md`, which subagents never touch).
- **Acceptance criteria:**
  - [ ] Both values are recorded with the date and the commit they were measured on
  - [ ] `check:full` passes with the baseline in place
- **Verification:** `npm run check:full`.
- **Dependencies:** T9
- **Files likely touched:** `CONSTRAINTS.md`
- **Estimated scope:** XS

**Checkpoint: Quality gates** (after T5–T10)
- [ ] `check:fast`, `check:task` and `check:full` run every check `CONSTRAINTS.md` lists; CI is green on `main` (spec criteria 6, 10)
- [ ] Every gate was seen failing on a planted violation
- [ ] From here, every ticket passes `check:task` before review and `check:full` before merge

## Risks and Mitigations

| Risk | Impact | Mitigation |
|---|---|---|
| Tauri 2 / WebKitGTK system packages missing or mismatched on Linux | High | T1 goes first; whatever it needed is written into `BUILDING.md` in T13 |
| Code written from Tauri v1 memory (APIs changed a lot in v2) | Med | Check Tauri 2's official docs while implementing T1 and T3 |
| Rust compile times push `check:task` over 3 minutes | Med | `cargo test -p` for touched crates only; measured in T7; if over, raise it with the user rather than drop a check |
| `diff-cover` merging Rust and TS lcov paths | Med | T7 must show a failure on both sides before it counts as done |
| Gate tools (gitleaks, osv-scanner, semgrep, cargo-llvm-cov, diff-cover) not installed on the dev machine | Low | Listed as contributor prerequisites in T13; the scripts fail with an install hint when a tool is missing |
| Parallel subagents conflicting on `package.json` | Low | The tasks that edit it are chained by dependencies |
